## 第一部分：三模块关联框架（逻辑主线）

### 一条主线：从“设计知识”到“装配执行”的语义贯通

大论文回答一个完整问题：**如何让机器自主地从产品设计信息出发，生成可被柔性装配系统直接执行的装配方案**。三模块是同一条链上前后衔接、缺一不可的三段：

```
┌──────────────────────────────────────────────────────────────────────┐
│  模块A  本体与知识图谱构建              [知识底座 Knowledge Foundation]  │
│  多源异构设计文档+图像+STEP ──→ 可溯源装配工艺知识图谱 K                 │
│  产物:本体 O=(C,R,H,A)、可溯源三元组 t̂=(h,r,t,σ)                       │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ K 作为"工艺语义先验"供检索
                               ▼
┌──────────────────────────────────────────────────────────────────────┐
│  模块B  装配序列生成 (本篇小论文)        [决策核心 Decision Core]        │
│  K + CAD几何 + 视觉 ──[APO+KRA+PFA+VES 零信任证据闭环]──→ S=⟨s₁..sₙ⟩    │
│  每步 sᵢ=(零件, 工艺语义 ωᵢ, 证据 Eᵢ)                                   │
│  ωᵢ=(prim工艺原语, (B,M)角色, F配合面, Θ姿态, Γ工装要求)                │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ ωᵢ 作为"工艺意图"驱动执行规划
                               ▼
┌──────────────────────────────────────────────────────────────────────┐
│  模块C  装配动作与资源规划              [执行落地 Execution Grounding]   │
│  ωᵢ + 装配系统资源库 ──→ 设备选型 · 夹持器选择 · 夹具选择 · 装配动作      │
│  把"工艺意图"实例化为"特定产线上的可执行作业"                            │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键洞察：模块间是“字段级强耦合”，不是松散拼接

这是大论文逻辑能“相互关联”而非“三篇拼凑”的命门——模块B输出的 ω_i，其每个字段恰好是模块C的输入：

| 模块B输出字段（ω_i） | 直接驱动模块C的哪个决策 |
|---|---|
| prim 工艺原语（螺纹紧固/压合/堆叠/焊接） | 设备选型：决定需拧紧轴/压机/焊枪等何种工艺设备 |
| Γ 工装要求（候选夹持器类别、夹持面） | 夹持器选择：直接给出末端执行器候选集 |
| (B,M) 基座/移动件 + F 配合面 | 夹具选择/定位方案：基座件如何固定、定位基准在哪 |
| Θ 姿态（接近方向、插入轴） | 装配动作规划：机器人接近路径与对位运动 |
| E_i 证据 + σ 来源 | 可追溯性贯通全链：执行方案可回溯到设计依据 |

→ 模块B不是“只产顺序”的传统ASP，它产出的ω_i是专为衔接模块C设计的中间表示。这是大论文区别于“三个独立工作”的核心论证，务必在引言点明。

### 模块A如何同时支撑B和C

模块A本体O必须同时容纳工艺语义和资源语义：
- 支撑B：Action / Material / 配合关系 / 优先约束（工艺语义先验）
- 支撑C：Equipment / Workstation / 夹持器-工艺匹配规则 / 夹具-零件匹配规则（资源语义）

本体四层中的**“物理实体与作业行为层（Action/Material/Equipment/Workstation）”**正是模块C的资源语义入口——本体设计已为模块C预留接口，大论文要把这层“激活”出来讲。

### 贯穿三模块的统一红线：可追溯性（provenance σ）

- 模块A：每条三元组可回溯到文档/图像/STEP（构建期溯源）
- 模块B：每步工艺语义可回溯到证据E_i与三元组（决策期溯源）
- 模块C：每个资源选择可回溯到ω_i字段与支撑规则（执行期溯源）

→ 大论文统一理论命题：**「设计—工艺—执行」全链路证据可追溯性**——比小论文的“装配序列可溯源”高一个层级，是大论文理论贡献锚点。

## 第三部分：研究缺口与大论文创新空间

> 可直接写入现状章节末尾

综合上述六条线索，可提炼大论文的整体研究缺口：

**1. 模块A构建侧已较成熟，但少有为“下游序列生成+执行规划”专门设计的本体**——现有装配工艺KG多服务于检索/问答/重用（胡志强2024、刘鸣飞2026、赖赞有2025），本体未预留资源语义与执行接口。

**2. 模块B输出语义贫乏、经验不可溯源**——国内最近的蒋明杰2024已用KG+本体做装配序列，但仍是“KG作优先约束的图搜索”，无运行时证据闭环、无成套工艺语义、无溯源（本篇小论文已论证并解决）。

**3. 模块C普遍是孤立工具、依赖人工输入工艺意图**——设备选型停留在静态MCDM（Hagag2023/Tran2024）、夹持器选择刚进入LLM开放语义阶段（GraspGPT）、夹具设计刚出现KG配置级应用（Meng2024），三者彼此割裂，且都缺少“从工艺语义自动驱动资源选择”的上游接口。

**4. 集成层：缺少以可溯源知识为底座、贯通“设计→工艺→执行”的统一框架**——现有DT与知识驱动系统（清华五要素模型2024、郭飞燕2019、Liu2021）止于框架/语言层，未把选型决策形式化、未建立全链路证据可追溯。

→ **大论文总命题**：以可溯源装配工艺知识图谱为统一底座（A），以KG先验+多智能体证据闭环生成带成套工艺语义的装配序列（B），再以序列的工艺语义ω_i级联驱动设备/夹持器/夹具的协同选择与装配动作规划（C），实现“设计—工艺—执行”全链路证据可追溯的智能装配决策方法。

**最近对照基线建议**：
- 整体框架 → 清华五要素模型（机械工程学报2024）、Liu2021（JMS DT装配框架）
- 模块B → 蒋明杰2024、Xie2025
- 模块C → Yang2022（CIE 选型+序列耦合）、Meng2024（KG夹具）、GraspGPT（LLM抓取）
