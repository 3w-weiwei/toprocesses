## 3 方法(Method)

### 3.1 总体架构

本文提出一种面向成套工艺语义的知识图谱与多智能体相结合的装配序列生成方法(见图 1)。其核心思想是将“工艺知识的组织”与“装配序列的推理”解耦为两个相互衔接的阶段：知识图谱负责把分散、异构、语义不互通的设计/工艺知识在领域本体约束下编译为统一可查、可溯源的外部知识源，解决“知识从哪来、如何高效组织”；多智能体负责依据该知识与运行时几何/视觉信息推理装配序列，解决“如何依据知识与信息推理出可执行且可溯源的序列”。该方法以产品的 CAD/STEP 模型与多源异构设计/工艺知识为输入，以一条带成套工艺语义且每步可溯源的装配序列为输出。

- **阶段一(知识构建，§3.2)**：一条 LLM/LMM 驱动的离线知识图谱构建流水线，从多源异构文件(工艺文档、图像、STEP 模型)中，在领域本体约束下抽取实体、关系与属性，将散落知识一次性编译为持久化、可溯源、可增量维护的工艺知识图谱 $\mathcal{K}$，供阶段二按需检索。
- **阶段二(序列规划，§3.3–§3.7)**：采用主从编排式(orchestrator–specialist)多智能体范式，由装配规划编排智能体(Assembly Planning Orchestrator, APO)作主智能体，知识检索智能体(Knowledge Retrieval Agent, KRA)、零件特征分析智能体(Part-Feature Analysis Agent, PFA)、视觉证据选择智能体(Visual-Evidence Selection Agent, VES)作专项子智能体。APO 理解任务、评估复杂度、按需调度子智能体，综合工艺知识、零件特征与视觉信息推导序列；子智能体之间互不通信，均经 APO 中转，以保证控制流确定、可复现。

两阶段以“构建—消费”职责解耦为基本原则：多智能体编排仅作用于知识的规划性消费，而非构建侧的三元组抽取。各智能体的角色、专属工具、可加载技能包与输入/输出接口如表 1所示。

**问题形式化**。给定由 $n$ 个零件构成的产品，记零件集合 $P={p_1,\dots,p_n}$。方法输入为三元组 $(\mathcal{G}_{cad},\mathcal{V},\mathcal{K})$：$\mathcal{G}_{cad}$ 为 STEP 解析的几何信息，$\mathcal{V}$ 为按需获取的视觉信息，$\mathcal{K}$ 为知识图谱工艺语义知识。目标为求一条装配序列 $S=\langle s_1,\dots,s_n\rangle$，每步 $s_i=(p_{\pi(i)},\omega_i,\mathcal{E}_i)$ 携带零件、工艺语义 $\omega_i$(Definition 5)与信息引用 $\mathcal{E}_i$，$\pi$ 为 $P$ 的一个排列，且满足：
- (C1) $S$ 是约束图 $D$(Definition 4)的拓扑排序；
- (C2) 每步沿声明方向无碰撞；
- (C3) 每步 $\omega_i$ 由不低于阈值层级 $\tau$ 的信息支撑(Definition 3)。

当知识不足以满足 (C3) 时，登记知识缺口 $\mathcal{R}$。方法输出为二元组 $(S,\mathcal{R})$。装配序列生成由此被刻画为：知识图谱工艺知识与运行时证据共同支撑的、带工艺语义的拓扑排序搜索问题。

> **实现状态说明**。阶段二(APO/KRA/PFA/VES 规划闭环)已在原型系统中实现并可运行；阶段一(知识图谱构建流水线)的多源预处理与文档型知识库已实现，其向模式层/实例层分离的形式化图谱与若干抽取/对齐组件为本文方法设计，部分仍在实现中。下文对“已实现”与“方法设计”予以区分。

### 3.2 多源异构装配工艺知识图谱构建

装配工艺知识天然分散于工艺文档、工艺图像与三维模型之中，呈现多源、异构、语义隐含的特点：同一配合关系可能在 PDF 文本中以自然语言描述、在爆炸图中以图形呈现、在 STEP 模型中以几何约束隐含。若令规划智能体在推理时逐次面对这些原始文件，既需反复解析又难以跨源关联。本文因此先离线将其编译为结构化、可溯源的知识图谱，使工艺语义以统一、可查询的形式持久存在。该阶段任务形式化为：

$$
\mathrm{KG\text{-}Pipeline}: (\mathcal{D},\ O) \to \mathcal{K},\qquad \mathcal{D}={d_{pdf}, d_{img}, d_{step}} \tag{1}
$$

其中 $\mathcal{D}$ 为多源异构文件集合，$O$ 为领域本体，$\mathcal{K}$ 为可溯源知识图谱。本文采用先建本体、再以本体约束抽取的自顶向下策略：先构建统一的领域本体作为模式约束，可在多源异构数据整合、增量更新与长期演化中持续提供稳定的语义一致性约束，从源头保证不同来源、不同模态的知识落入同一概念体系。产出 $\mathcal{K}$ 在逻辑上分为三层——模式层(领域本体 $O$，规定概念类型、关系语义与一致性公理)、实例层(由大模型抽取、去重后写入的可溯源三元组集合)、多模态溯源层(保存文档块、图像与 STEP 组件的原始制品，作为不可变事实来源)。

> **构建侧范式选择**。与将多智能体编排投入 KG 构建侧的近期工作(MA-APKG [Pu et al., 2026]、KARMA [Lu & Wang, 2025])不同，本文主张在装配工艺场景下，KG 构建可由一条 LLM/LMM 驱动的离线流水线经济地完成：构建侧的核心诉求是抽取的准确性与可溯源性，可由 Schema 约束与 grounding 机制保证，无需运行时的多智能体协商；而多智能体的价值应转移到知识的规划性消费侧(§3.3–§3.7)，用于动态、不确定的序列推理。

> **【图 2 位置】** KG 三层架构与构建流水线图(示意图，待绘制)：上方模式层(本体 $O$)→ 中部实例层(可溯源三元组)→ 下方多模态溯源层(原始制品)；左侧三类文件(PDF/图像/STEP)沿各自抽取路径(文本抽取/图像理解/几何映射)写入实例层，每条三元组经来源算子 $\sigma$ 回链溯源层。

#### 3.2.1 领域本体设计

本体先于抽取定义，作为模式约束贯穿整条流水线，既为抽取提供类型与关系的取值空间，又为跨模态实体归并提供唯一性依据。

> **Definition 1(装配工艺本体)**。装配工艺本体定义为四元组 $O=(C,R,H,A)$。概念类 $C$ 按四个逻辑层级组织：过程结构与上下文层(Doc、Step)；物理实体与作业行为层(Action、Material、Equipment、Workstation)；数据要素与信息流转层(Param、Sink)；多模态资源关联层(Image/ImageExtract、StepModel/StepComponent)。$R$ 为关系类型集合(如 HAS_CHUNK、HAS_IMAGE、HAS_COMPONENT、HAS_ASSEMBLY_RELATION 等)，$H$ 为概念层级(is-a 继承)，$A$ 为约束与公理——唯一性约束实现同名实体自动归并去重，多维索引保障跨模态检索效率。

四层划分对应装配工艺知识的内在结构：过程层承载“做什么、按何顺序”，实体层承载“用什么、对什么作业”，数据层承载“参数与信息流向”，资源层将前三层锚定到可溯源的原始制品。各层及其典型关系类型见表 2。

> **【表 2 位置】** 本体概念类与关系类型表(建议新增)：按四个逻辑层级列出概念类 $C$、典型关系 $R$(头实体—关系—尾实体)与关键约束 $A$，使 Definition 1 的抽象四元组落地为可读清单(可参照 MA-APKG 表2–4 的“编号/头实体/关系/尾实体”格式)。

#### 3.2.2 知识获取与预处理

预处理负责把原始文件转换为可被大模型消费、且可回链溯源的中间表示，据此建立多模态溯源层。按文件类型分别处理：

- **工艺文档(PDF)**：以 PyMuPDF 解析获取文本、图片与图文关联；采用递归字符分块在可控长度下保留语义关联；文本块经嵌入存入 FAISS 向量库，并在 Neo4j 中建立 Document—Chunk—Image 节点结构，使后续抽取的三元组可回指具体文档块；
- **图像**：按工艺语义归为六类(装配工艺流程图、零件三维模型图、产品爆炸图、设备实物图、设备示意图、未知)，统一尺寸并编码，嵌入 FAISS，在 Neo4j 建立 Image 节点；
- **STEP 模型**：以 PythonOCC 解析，提取装配层次、零件级几何与拓扑、几何特征(圆柱面/平面)及基于几何关系的装配约束(共轴、共面)，输出结构化 JSON，在 Neo4j 建立完整图结构。

三类预处理结果统一以节点形式沉淀于溯源层，成为来源算子 $\sigma$(Definition 2)的回链目标。

#### 3.2.3 基于大模型的文本知识抽取

文本抽取采用 Schema 驱动、本体约束下的结构化抽取。将本体概念 $O$ 序列化为 JSON Schema 注入大模型上下文，利用 LLM 的函数调用能力把非结构化文本解析转化为“参数填充”任务。对文档块 $y$，抽取过程可形式化为：

$$
\hat{T}_{text}(y) = \mathrm{LLM}\big(y \mid \mathrm{Schema}(O),\ F_{shot}\big)\ \odot\ O \tag{2}
$$

其中 $F_{shot}$ 为少样本示例，$\odot O$ 表示本体一致性过滤——仅保留概念类型与关系类型均在 $O$ 取值空间内、且满足约束公理 $A$ 的三元组，类型非法者剔除。为抑制生成式幻觉，抽取施加精确片段截取(grounding)约束：强制模型从原文截取连续子串作为实体/属性取值，严禁改写或臆造。输出经自动化解析器做反序列化与完整性校验，确保每条知识在格式与类型上符合本体定义。该设计使文本抽取的每条三元组都同时满足“类型合法(由 $\odot O$ 保证)”与“原文有据(由精确截取保证)”两重约束。

#### 3.2.4 基于多模态模型的图像知识理解

图像理解采用“分类—模板引导”两阶段。先由 LMM 将图像归类(语义路由)$c=\mathrm{LMM}_{cls}(d_{img})$，再对类别 $c$ 施以特有模板按需抽取并经本体过滤：

$$
\hat{T}_{img}(d_{img}) = \mathrm{LMM}\big(d_{img} \mid \mathrm{Tmpl}(c)\big)\ \odot\ O \tag{3}
$$

不同类别触发不同抽取目标：流程图抽取步骤序列与流转关系；爆炸图/三维模型图抽取组件列表、装配顺序、几何特征与材料；设备类图像抽取主要功能、关键部件与操作注意事项。语义路由先收敛图像的语义类型，使后续抽取在受限模板下进行，既提升抽取针对性，也降低跨类别的语义混淆。

#### 3.2.5 知识图谱构建流程

> **Definition 2(可溯源三元组)**。一条可溯源三元组定义为 $\hat t=(h,r,t,\sigma)$，其中 $(h,r,t)$ 为本体约束下的标准三元组，$\sigma$ 为来源算子，$\sigma(\hat t)\to d$ 将其映射至来源(文档块、图像或 STEP 组件)。所有实例层知识构成 $\mathcal{K}={\hat t}$，以 Neo4j 图存储、FAISS 向量索引支持跨模态检索。

三类抽取结果 $\hat{T}_{text}\cup\hat{T}_{img}\cup\hat{T}_{step}$ 经统一的本体一致性与唯一性校验后写入实例层，每条绑定来源 $\sigma$。端到端流程如 Algorithm 1 所示。

> **【Algorithm 1 位置】** LLM/LMM 驱动的多源异构知识图谱构建
> 
> **输入**：多源文件 D={d_pdf, d_img, d_step}；领域本体 O=(C,R,H,A)
> 
> **输出**：可溯源知识图谱 K
> 
> ```
> 1: K ← ∅
> 2: for each d ∈ D do
> 3:    预处理：按类型解析并建立多模态溯源层节点(嵌入 FAISS)
> 4:    if d 为文本 then  T_d ← LLM(chunks | Schema(O), 少样本, 精确截取) ⊙ O
> 5:    elif d 为图像 then T_d ← LMM(d | 分类模板) ⊙ O
> 6:    else               T_d ← 几何关系转三元组(PythonOCC 解析结果)
> 7:    for each (h,r,t) ∈ T_d do
> 8:       校验本体一致性与唯一性约束(类型合法；去重归并)
> 9:       if 通过 then  K ← K ∪ {(h,r,t,σ=d)}  # 绑定来源，写入 Neo4j
> 10:      else 登记待人工复核
> 11: return K
> ```

### 3.3 主从编排式多智能体框架与智能体构成

本节阐明阶段二四个规划智能体共享的统一构建范式：框架基础、编排运行机制与智能体构成要素。

**框架运行流程**。各智能体基于 MCP(Model Context Protocol)框架构建(见图 3)。运行流程如下：当规划需求被发起时(Step 1)，控制器代码经 MCP 接口调用智能体模块；智能体内部与 LLM/LMM 交互(Step 2)，根据任务动态选择工具并分解执行(Step 3)。基于 MCP 框架定义的智能体可通过结构化输出约束与多轮对话实现自反思与迭代改进，持续优化其响应质量。

**编排运行机制(四环节)**。整个规划阶段并非固定流水线，而是 APO 依据任务状态按需调度子智能体的迭代过程，可归纳为四个环节(对应 §3.4.3 Algorithm 2)：

1. **任务理解与范围建立**：APO 接收 CAD/STEP 模型与规划目标，调用模型范围工具获取装配树、零件清单与包围盒等几何事实，评估装配体规模与复杂度，据此规划后续需要哪些子智能体介入、对哪些关键零件与配合关系优先取证；
2. **按需委派专项子智能体**：APO 根据子任务类型动态分配持有对应提示词、工具与技能包的子智能体——需要工艺语义知识时委派 KRA 检索知识图谱、返回可溯源三元组；需要零件级特征时委派 PFA 提取几何类别、装配特征与候选夹持面；需要空间确认时委派 VES 捕获接触面、运动方向等视觉信息；
3. **综合分析与约束推导**：APO 汇聚 KRA 的工艺知识、PFA 的零件特征与运行时接触启发式，形成候选优先约束集；对每条候选约束综合几何与视觉信息评估其可信度，必要时再次委派 VES 补充视觉信息并迭代；信息充分者采纳并写入约束图 $D$，不足者降级并登记知识缺口 $\mathcal{R}$；
4. **序列生成与输出**：APO 对约束图 $D$ 作拓扑排序得到装配序列 $S$，为每步填充工艺接口规范并绑定支撑信息来源，输出 $(S,\mathcal{R})$。

该机制的关键在于 APO 是决策中枢而非顺序执行器——它判断“当前需要什么、该问谁”，将专业子任务下放给装载对应 Skill 的子智能体，自身专注于知识与信息的综合及序列推导。

**范式有效性**。本文采用主从编排式范式而非单体大模型端到端输出，源于装配序列规划任务的内在结构：它天然可分解为“全局序列编排”与若干“专项取证”子任务，且各子任务所需能力、上下文与信息类型互不相同。该范式的有效性来自三条独立机制：
(1) **职责分解抑制知识漂移**——每个智能体仅在受限上下文与明确能力边界内工作，从源头压缩幻觉空间；
(2) **主从编排匹配任务中枢依赖结构**——约束图构建与拓扑排序须由统揽全局者完成，知识、特征与视觉是按需调用的局部服务，主从关系使控制流确定、可复现，避免对等协商的不可控收敛与冗余通信；
(3) **工具与技能装载将“猜测”约束为“有据可依的推断”**——各智能体的结论须绑定外部信息来源，使输出从“基于参数记忆的生成”转变为“基于外部信息的推断”。

每个规划智能体由四个要素组合构成其专家能力，下分三节阐述其核心三者(角色界定隐含于 §3.3.1 三阶段提示词的第一阶段)。

> **【图 3 位置】** MCP 智能体运行流程图：Step 1 控制器经 MCP 接口调用 → Step 2 智能体与 LLM/LMM 交互 → Step 3 动态选择工具并分解执行 → 结构化输出 + 多轮自反思回路。

#### 3.3.1 三阶段提示词设计

每个智能体的能力通过三阶段提示词设计增强，以结构化框架实现任务驱动执行与逻辑引导：

1. **角色定位阶段**：按任务需求分配专业身份(如 APO 为“装配规划编排专家”、KRA 为“工艺知识检索专家”、PFA 为“单零件装配特征分析专家”、VES 为“视觉证据选择专家”)，明确知识体系与能力边界，将模型严格约束在指定专业域内生成，从源头减少因角色模糊导致的知识漂移与幻觉；
2. **任务依据与输入信息阶段**：系统化注入多源数据与工具资源——明确输入数据覆盖的关键要素并清晰定义所需工具及其功能，为模型提供稳健的上下文支撑，防止因信息缺失而产生幻觉，约束生成内容不偏离事实依据；
3. **具体任务要求阶段**：以渐进逻辑构建任务体系并明确输出格式；通过任务概述与示例描述确保输出格式一致性与逻辑严密性，防止模型在复杂推理中出现逻辑断裂与内容发散。

三阶段共同构成闭环引导：角色定位约束“以谁的身份做”，任务依据约束“基于什么做”，任务要求约束“做成什么样且不得越界”，对应范式中“职责分解”机制在单个智能体内部的落地。在此框架下，各智能体提示词进一步结合示例引导(Example-Guided)、上下文(Contextual)、指令式(Instructional)与思维链(Chain-of-Thought)等提示工程技巧，以提升复杂推理的稳定性与输出一致性。

#### 3.3.2 专属 MCP 工具与可加载技能包(Skill)

专属 MCP 工具为各智能体提供与运行时环境交互的外部能力(几何解析、视觉渲染、KG 查询等)，是智能体获取 $L_0$–$L_3$ 信息(Definition 3)的通道；可加载技能包(Skill)针对特定子任务封装领域启发式与操作规程，在智能体被调度时按需加载，使其即时装载对应专长而非依赖通用推理临场发挥。二者随角色而异，配置见表 1。这一设计将智能体的能力来源外置化：每一步专业判断都可回溯到其调用的工具或加载的 Skill，而非模型参数的隐式输出，是范式有效性机制(3)在工程上的落地。

#### 3.3.3 结构化输出约束

结构化输出契约以 JSON Schema 规定各智能体的返回字段，承担两项功能：其一，保证子智能体返回的工艺知识、零件特征与视觉信息以统一格式汇入 APO 的约束推导，可被直接解析、聚合与追溯；其二，强制每条结论携带其信息来源引用(对应 Definition 3 的证据使用规则)，使“结论—证据”绑定在数据结构层面得到保证。

### 3.4 装配规划编排智能体(APO)：综合知识与视觉信息的序列推导

APO 是规划阶段的中枢主智能体。它不直接凭直觉给出装配顺序，而是调度 MCP 工具与子智能体(KRA、PFA、VES)，综合知识图谱中的工艺知识与运行时几何/视觉信息，构建约束图并推导序列。其任务形式化为：

$$
\mathrm{APO}: (\mathcal{G}_{cad},\ \mathcal{K}) \to (S,\ \mathcal{R}) \tag{4}
$$

其中 $\mathcal{G}_{cad}$ 为 STEP 几何，$\mathcal{K}$ 为知识图谱(阶段一离线构建，由 APO 经 KRA 按需查询)，$S$ 为装配序列，$\mathcal{R}$ 为知识缺口。APO 接收任务后，先调用模型范围工具建立 $L_0/L_1$ 几何范围，再据子任务类型分派 KRA/PFA/VES 取证，继而在信息可信度分级(§3.4.1)之上构建约束图(§3.4.2)、执行证据驱动的多轮规划分析(§3.4.3)，最终输出带工艺语义且可溯源的序列(§3.4.4)。

#### 3.4.1 信息可信度分级与证据使用规则

APO 在推导中依据的信息来自异构来源，可信度与可溯性各不相同。为使智能体对不同来源恰当加权，本文将其组织为五级偏序：

> **Definition 3(信息可信度分级)**。信息空间为偏序集 $\mathcal{E}={L_0,L_1,L_2,L_3,L_4}$，$L_0\prec L_1\prec L_2\prec L_3\prec L_4$：
> - $L_0$：元数据事实；
> - $L_1$：几何事实(装配树/包围盒/面/法向/面积/拓扑)；
> - $L_2$：视觉制品(以图像路径为凭)；
> - $L_3$：启发式候选(接触候选、清障/拆卸方向、阻挡件，带置信度与方法标记)；
> - $L_4$：智能体推断。
>
> $L_0/L_1$ 由 STEP 解析直接给出，$L_2$ 为视觉确认，$L_3$ 明确标注为启发式而非精确求解。

在此分级之上，APO 遵循一组证据使用规则：不得将 $L_3$ 启发式置信度当作事实；不得仅凭零件名称或外观断言功能、材料、过盈、扭矩、焊接、胶接或装配力；不得将直线拆卸方向当作完整机器人路径；不得将工具 JSON 元数据当作视觉证据($L_2$ 必须有图像路径)。形式化地，步骤 $s_i$ 的工艺语义 $\omega_i$ 被赋高置信，当且仅当其支撑信息 $\mathcal{E}_i$ 含层级不低于阈值 $\tau$ 的来源(即约束 C3)。

> **【表 3 位置】** 五级信息可信度与证据使用规则对照表(建议新增)：逐级列出 $L_0$–$L_4$ 的来源、获取工具、典型实例与对应禁用规则，使 Definition 3 与证据规则可对照查阅。

#### 3.4.2 约束图构建

> **Definition 4(约束图)**。装配约束图为有向图 $D=(N,A)$，节点 $N$ 为零件或子装配，边 $A={(n_a,n_b,\delta,\beta,\mathcal{E}_{ab})}$ 表示 $n_a$ 优先于 $n_b$，$\delta$ 为依赖类型(空间前置、配合顺序、可达性保持、阻挡优先、封闭优先、子装配合并、紧固前置、工装前置)，$\beta\in{\mathrm{hard,soft}}$ 区分硬约束与软/推断约束，$\mathcal{E}_{ab}$ 为支撑信息引用。$D$ 须无环；环或矛盾依赖登记入 $\mathcal{R}$。

APO 构建 $D$ 时，依据 KRA 返回的工艺知识与运行时几何/视觉信息共同推导优先边，其优先规则源自工艺本体公理(如内部件先于封盖、定位件先于依赖件、紧固件后于被紧固件、阻挡件后于被阻挡件)。每条边均携带 $\beta$ 标记其约束强度与 $\mathcal{E}_{ab}$ 标记其来源，为后续可信度评估与溯源提供依据。

#### 3.4.3 证据驱动的多轮规划分析

APO 区别于单轮大模型推理的核心，是证据驱动的多轮规划分析：候选优先约束来自 KRA 检索的工艺知识与运行时接触启发式；APO 综合几何与视觉信息评估每条候选约束的可信度——获得不低于 $\tau$ 层级信息支撑者进入高置信结论并写入约束图，信息不足者降级并登记知识缺口，而非强行采纳。其过程如 Algorithm 2 所示。

> **【Algorithm 2 位置】** APO 证据驱动的多轮规划分析
>
> **输入**：CAD 几何 G_cad；知识图谱 K；可信度阈值 τ；最大轮数 K_max
>
> **输出**：装配序列 S；知识缺口 R
>
> ```
> 1: M ← {model_summary, assembly_tree, parts}     // 任务理解：建立 L0/L1 范围
> 2: for each 关键零件 p_i do φ_i ← PFA(p_i)        // 委派特征分析
> 3: T̂ ← KRA(知识需求, K)                          // 委派检索：返回可溯源工艺知识
> 4: C ← cad_get_contact_pairs(compact=true)       // L3 接触候选
> 5: D ← ∅; R ← ∅
> 6: for each 候选约束 c ∈ (T̂ ∪ C) do              // 候选来自知识与接触启发式
> 7:    k ← 0; E_c ← 收集信息(c, M)                // L0/L1
> 8:    while level(E_c) < τ and k < K_max do
> 9:       e_vis ← VES(claim=c, G_cad)              // 补充 L2 视觉信息
> 10:      E_c ← E_c ∪ {e_vis}; k ← k+1
> 11:   if level(E_c) ≥ τ then D ← D ∪ {edge(c,β,E_c)} // 信息充分，采纳
> 12:   else R ← R ∪ {gap(c,"信息不足",E_c)}        // 信息不足，登记缺口
> 13: if D has cycle then R ← R ∪ {矛盾依赖}
> 14: S ← TopologicalSort(D)                       // 满足 C1
> 15: for each s_i ∈ S do
> 16:    s_i.ω_i ← ProcessInterface(s_i, T̂, E)     // 填充 Definition 5
> 17:    if s_i 无有效 L2 视觉信息 then s_i.conf←low; R←R∪{s_i}
> 18: return (S, R)
> ```

该过程使每条工艺约束的采纳都与其支撑信息的可信度相匹配(第 11–12 行)：信息充分则采纳，不足则显式登记缺口而非强行补全(第 12、17 行)，这是本文方法在工业场景下的安全性来源。

#### 3.4.4 带工艺语义且可溯源的装配序列输出

经 Algorithm 2 得到的序列遵循统一结构化模式，每步携带工艺接口规范。

> **Definition 5(工艺接口规范)**。步骤 $s_i$ 的工艺语义 $\omega_i=(\mathrm{prim},(B,M),F,\Theta,\Gamma)$：
> - $\mathrm{prim}$ 为工艺原语(平面配合、圆柱插入、轴孔插入、螺纹紧固、堆叠、封盖等)；
> - $(B,M)$ 为基座件/移动件角色划分；
> - $F$ 为配合/支撑/对齐面引用；
> - $\Theta$ 为姿态要求(接近方向、插入轴、旋转轴、姿态约束)；
> - $\Gamma$ 为工装要求(候选夹持器、夹持面、需保持清空面、所需能力及尚缺外部输入)。

这些字段被定位为指导下游柔性装配台/机器人规划的候选工艺意图，而非最终轨迹或确定夹具设计。结合每步绑定的信息引用 $\mathcal{E}_i$ 与来源算子 $\sigma$，整条序列实现从设计文档到装配步骤的逐步可溯源。

> **关于视觉理解的说明**。装配产品的视觉理解仍是开放难题。本文不声称解决该难题，而是通过 VES、多视角/剖切渲染工具与主从编排，在前述证据使用规则下最大化可获取的视觉信息，并对视觉不确定步显式标记待人工复核(Algorithm 2 第 17 行)，而非强行判断。

### 3.5 知识检索智能体(KRA)：本体约束下的可溯源知识检索

KRA 为 APO 的专项子智能体，负责将 APO 的知识需求转化为对知识图谱的结构化查询，并返回可溯源的工艺语义知识。其任务形式化为：

$$
\mathrm{KRA}: (\text{need},\ \mathcal{K}) \to \hat{T},\qquad \hat{T}={\hat t_1,\dots,\hat t_m} \tag{5}
$$

其中 $\text{need}$ 为 APO 下达的知识需求(如“零件 $p_a$ 与 $p_b$ 的配合类型与连接工艺”)，$\hat{T}$ 为返回的可溯源三元组集合，每条 $\hat t=(h,r,t,\sigma)$ 携带来源算子 $\sigma$(Definition 2)。

KRA 接收需求后，将其分解为“定位—下钻”的检索子任务并依次调度三个 MCP 工具。不同于将大子图一次性注入上下文的检索增强方式(社区摘要会损失精确约束，冗余子图不可溯)，KRA 采用模式引导、索引优先、本体约束下的类型化多跳检索，逐跳按需取证：

1. **模式层引导(查询规划)**：以 kg_schema_peek 读取领域本体 $O$ 作为导航地图，将 $\text{need}$ 映射为本体上的查询计划——确定相关实体类型与关系类型，把开放式知识需求收敛为类型受限的检索目标；
2. **入口实体定位(锚定)**：以 kg_entity_resolve 在实例层定位种子实体——借助 FAISS 语义检索处理同义/别名表述，并以本体唯一性约束完成“模糊名→标准实体”消歧，得到锚点；
3. **类型化多跳遍历(下钻)**：以 kg_path_query 自锚点出发，仅沿本体允许的关系类型作多跳路径检索(Neo4j Cypher)，按需扩展邻域并逐跳返回三元组；每跳经 $\sigma$ 绑定其文档块/图像/STEP 组件来源，使返回知识整体可回链原文。

KRA 严格遵守证据使用规则：仅返回知识图谱中实际存在的三元组及其来源，不得生成式补全图谱中不存在的关系；当查询计划在图谱中无匹配路径时，返回空集并标注为知识缺口，交由 APO 处理(Algorithm 2 第 12 行)，而非臆测。

### 3.6 零件特征分析智能体(PFA)：单零件装配特征提取

PFA 为 APO 的专项子智能体，负责对单个零件做稳定、可追溯的装配特征提取。其任务形式化为：

$$
\mathrm{PFA}: p_i \to \phi_i \tag{6}
$$

PFA 接收零件 $p_i$ 后，仅调用一次 cad_render_part_multiview(返回 8 视角图像 + compactPart 几何统计)，据此并行分析五类特征并汇总为结构化特征向量 $\phi_i$：

- **几何类别**：plate / disk / shaft / block / ring / fastener_like / spring_like / seal_like / freeform / mixed / unknown；
- **装配特征**：hole / through_hole / blind_hole / shaft / cylindrical_surface / planar_surface / thread_like / slot / notch / boss / step / keyway_like / pin_like / thin_wall / cover_like / orientation_feature；
- **对称性与方向性**：axisymmetric / rotational / mirror / bilateral / asymmetric，并记录缺口、偏心孔、键槽等定向特征；
- **候选面**：区分候选夹持面、装配面、支撑面与需避免接触面；
- **装夹策略推断**：给出候选夹持器/工装类别(如 vacuum_pad / v_block / three_jaw_chuck / magnetic_driver / inner_expansion)，但必须标注为工艺推断而非几何事实。

PFA 严格遵守信息使用规则：compactPart 的平面/圆柱面统计仅作 mesh_heuristic；不得仅凭图片断言材料、磁性、刚度、公差、装配力或螺纹标准，此类信息无外部输入时必须登记为“不确定信息”。

### 3.7 视觉证据选择智能体(VES)：最小上下文取证

VES 为 APO 的专项子智能体，职责是以尽量少的上下文，为某一待证明结论捕获并筛选最具信息量的视觉信息。其任务形式化为：

$$
\mathrm{VES}: (\text{claim},\ \mathcal{G}_{cad}) \to e_{vis} \tag{7}
$$

VES 接收待证明结论 claim 后，按目标类型选择工具策略：

1. **概览**：调用 cad_collect_visual_evidence(mode=overview)；
2. **接触对**：调用 cad_render_contact_pair_multiview，隔离两零件并以红色高亮候选接触面；
3. **拆卸/装入方向**：调用 cad_render_move_preview，仅在方向假设已提出时使用；
4. **隐藏界面**：调用 cad_collect_visual_evidence(mode=section_sweep) 扫掠剖切。

VES 的选择准则为：目标零件/接触面可见、运动方向可见、遮挡低、构图完整、视图状态干净、且图像确实支撑结论。若无有用图像，则将信息置空并给出重拍建议，而非强行引用。由于视觉工具共享 viewer 状态，VES 串行调用，并在每次独立取证前以 cad_reset_view_state 复位。
