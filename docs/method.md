3 方法(Method)

  3.1 总体架构

  本文提出一种面向成套工艺语义的知识图谱与多智能体相结合的装配序列生成方法(见图 1)。其核心思想包含两个相互衔接的部分:

  其一,以知识图谱作为多源异构数据的高效组织与外部获取方式。产品的设计文档、工艺图像与 STEP 模型分散、异构且语义不互通,直接交由大模型逐次检索既低效又难以复用。本文将这些散落知识在领域本体约束下抽取、互联并沉淀为一个结
  构化、可溯源的知识图谱,使工艺语义以统一、可查询的组织形式持久存在,为下游规划提供稳定的外部知识来源。

  其二,以多智能体依据知识图谱知识与视觉信息协同完成装配序列的规划分析。在序列推导阶段,多智能体一方面通过 KG 检索工具获取与零件、配合关系相关的工艺语义知识,另一方面调用 STEP
  运行时几何与多视角视觉信息,综合二者对装配优先关系、配合方式与工艺语义进行规划分析;当所获知识与视觉信息不足以支撑某一判断时,系统显式登记知识缺口,而非强行给出结论。

  由此,知识图谱负责"知识从哪来、如何高效组织",多智能体负责"如何依据知识与视觉信息推理出装配序列"。该方法以产品的 CAD/STEP
  模型与多源异构设计/工艺知识为输入,以一条带成套工艺语义且每步可溯源的装配序列为输出。整体流程细分为两个阶段:

  - 阶段一(知识构建):一条 LLM/LMM 驱动的离线知识图谱构建流水线,从多源异构文件(工艺文档、图像、STEP
  模型)中,在领域本体约束下抽取实体、关系与属性,将散落知识一次性编译为持久化、可溯源、可增量维护的工艺知识图谱,供阶段二的规划智能体按需检索。
  - 阶段二(序列规划):采用主从编排式(orchestrator–specialist)多智能体范式,由三个职责专一的规划智能体协同完成——装配规划编排智能体(Assembly Planning Orchestrator, APO)、零件特征分析智能体(Part-Feature Analysis Agent,
  PFA)与视觉证据选择智能体(Visual-Evidence Selection Agent, VES)。APO 作为中枢主智能体调度 MCP 工具与子智能体,综合 KG 工艺知识与运行时几何/视觉信息推导装配序列;PFA 与 VES
  为专项子智能体,分别承担零件级特征提取与视觉取证。

  总体流程。 端到端处理流程如下:

  1. (离线)知识编译:将多源异构文件经预处理、本体约束下的 LLM/LMM 抽取与一致性校验,编译为持久化知识图谱 $\mathcal{K}$;
  2. 范围建立:APO 调用模型范围工具获取装配树、零件清单与包围盒等几何事实,确立规划全局范围;
  3. 零件特征提取:APO 对关键零件委派 PFA,获取几何类别、装配特征与候选夹持面等特征;
  4. 知识检索与候选生成:APO 经 KG 检索工具从 $\mathcal{K}$ 获取工艺语义知识,与运行时接触候选合并为候选约束集;
  5. 多轮规划分析:对每条候选约束,APO 综合几何与视觉信息评估其可信度,信息不足时委派 VES 补充视觉信息并迭代;信息充分者采纳,否则降级登记知识缺口;
  6. 约束图构建:将采纳的约束组织为有向约束图 $D$;
  7. 序列生成:对 $D$ 拓扑排序得到序列 $S$,并为每步填充工艺接口规范;
  8. 输出:产出带工艺语义且逐步绑定信息来源的装配序列 $S$ 与知识缺口报告 $\mathcal{R}$。

  两阶段以"构建—消费"职责解耦为基本原则:多智能体编排仅作用于知识的规划性消费(步骤 2–8),而非构建侧的三元组抽取。三个规划智能体均以 LLM/LMM 为推理核心,并通过模型上下文协议(Model Context Protocol,
  MCP)调用各自的专属工具,实现从输入数据到设计产出的自动化流转。各智能体的角色、专属工具与输入/输出接口如表 2 所示。

  3.2 规划智能体构建范式

  本文三个规划智能体(APO、PFA、VES)共享统一的构建范式。本节阐明范式的设计选择、有效性来源及其核心机制。

  3.2.1 主从编排式多智能体框架

  各智能体基于 MCP(Model Context Protocol)框架构建(见图 2)。其运行流程如下:当规划需求被发起时(Step 1),控制器代码经 MCP 接口调用智能体模块;智能体内部与 LLM/LMM 交互(Step 2),根据任务动态选择工具并分解执行(Step 3)。基于
  MCP 框架定义的智能体可通过结构化输出约束与多轮对话实现自反思与迭代改进,持续优化其响应质量。

  本文采用主从编排式(orchestrator–specialist)范式而非单体大模型端到端输出。这一选择源于装配序列规划任务的内在结构:它天然可分解为"全局序列编排"与若干"专项取证"子任务,且各子任务所需的能力、上下文与信息类型互不相同。据此
  设置一个中枢编排者(APO)与两个专项执行者(PFA、VES),使控制流确定、职责边界清晰。该范式的有效性来自三条独立机制:

  1. 职责分解抑制知识漂移。 将全任务分解到边界清晰的专项智能体后,每个智能体仅在受限上下文内工作,从源头压缩幻觉发生空间。
  2. 主从编排匹配任务中枢依赖结构。 装配序列推导存在天然中枢——约束图构建与拓扑排序须由统揽全局者完成,而特征与视觉信息是按需调用的局部服务。主从关系使控制流确定、可复现。
  3. 工具化取证将"猜测"约束为"有据可依的推断"。 各智能体通过 MCP 工具从运行时几何、视觉渲染与知识图谱中获取信息;推理结论须绑定信息来源,使模型输出从"基于参数记忆的生成"转变为"基于外部信息的推断"。

  3.2.2 三阶段提示词设计

  通过引入 LLM/LMM 作为智能体的推理核心,每个智能体的能力通过三阶段提示词设计增强。三阶段提示词设计通过结构化框架实现任务驱动执行与逻辑引导:

  1. 角色定位阶段:按任务需求分配专业身份(如 APO 为"装配规划编排专家"、PFA 为"单零件装配特征分析专家"、VES
  为"视觉证据选择专家"),明确知识体系与能力边界,将模型严格约束在指定专业域内生成,从源头减少因角色模糊导致的知识漂移与幻觉。
  2. 任务依据与输入信息阶段:系统化注入多源数据与工具资源——明确输入数据覆盖的关键要素并清晰定义所需工具及其功能,为模型提供稳健的上下文支撑,防止因信息缺失而产生幻觉,有效约束生成内容不偏离事实依据。
  3. 具体任务要求阶段:以渐进逻辑构建任务体系并明确输出格式;通过任务概述与示例描述确保输出格式一致性与逻辑严密性,防止模型在复杂推理中出现逻辑断裂与内容发散。

  三阶段提示词构成闭环任务执行引导:角色定位约束"以谁的身份做",任务依据约束"基于什么做",任务要求约束"做成什么样且不得越界",对应范式中"职责分解"机制在单个智能体内部的落地。

  3.3 问题形式化

  给定由 $n$ 个零件构成的产品,记零件集合为 $P={p_1,\dots,p_n}$。方法输入为三元组 $(\mathcal{G}{cad},\mathcal{V},\mathcal{K})$:$\mathcal{G}{cad}$ 为 STEP 解析的几何信息,$\mathcal{V}$ 为按需获取的视觉信息,$\mathcal{K}$
  为知识图谱工艺语义知识。

  目标为求一条装配序列 $S=\langle s_1,\dots,s_n\rangle$,每步 $s_i=(p_{\pi(i)},\omega_i,\mathcal{E}_i)$ 携带零件、工艺语义 $\omega_i$(Definition 5)与信息引用 $\mathcal{E}_i$,$\pi$ 为 $P$ 的排列。所求序列须满足:

  - (C1) $S$ 是约束图 $D$(Definition 4)的拓扑排序;
  - (C2) 每步沿声明方向无碰撞;
  - (C3) 每步 $\omega_i$ 由不低于阈值层级 $\tau$ 的信息支撑(Definition 3)。

  当知识不足以满足 (C3) 时,登记知识缺口 $\mathcal{R}$。方法输出为二元组 $(S,\mathcal{R})$。装配序列生成由此被刻画为:知识图谱工艺知识与运行时证据共同支撑的带工艺语义拓扑排序搜索问题。

  3.4 多源异构装配工艺知识图谱构建

  阶段一的知识图谱构建为一条 LLM/LMM 驱动的离线流水线,负责将散落于多源异构文件中的离散知识,一次性编译为语义清晰、可溯源的知识图谱,供阶段二规划智能体通过 KG 检索工具按需查询。其任务形式化为:
  $$\mathrm{KG\text{-}Pipeline}: (\mathcal{D},\ O) \to \mathcal{K},\qquad \mathcal{D}={d_{pdf}, d_{img}, d_{step}} \tag{1}$$

  其中 $\mathcal{D}$ 为多源异构文件集合,$O$ 为领域本体,$\mathcal{K}$ 为可溯源知识图谱。产出 $\mathcal{K}$ 在逻辑上分为三层:多模态溯源层(保存文档块、图像与 STEP
  组件的原始制品,作为不可变事实来源)、实例层(由大模型抽取、去重后写入的可溯源三元组集合)、模式层(领域本体 $O$,规定概念类型、关系语义与一致性公理)。

  ▎ 构建侧范式选择。 与将多智能体编排投入 KG 构建侧的近期工作(MA-APKG [Pu et al., 2026]、KARMA [Lu & Wang, 2025])不同,本文主张在装配工艺场景下,KG 构建可由一条 LLM/LMM
  ▎ 驱动的离线流水线经济地完成,而多智能体的价值应转移到知识的规划性消费侧(§3.5)。

  3.4.1 知识获取与预处理

  原始文件先经结构化管理与向量化预处理,以建立多模态溯源层。按文件类型分别处理:

  - 工艺文档(PDF):以 PyMuPDF 解析获取文本、图片与图文关联;采用递归字符分块在可控长度下保留语义关联;文本块经嵌入存入 FAISS 向量库,并在 Neo4j 中建立 Document—Chunk—Image 节点结构;
  - 图像:按工艺语义归为六类(装配工艺流程图、零件三维模型图、产品爆炸图、设备实物图、设备示意图、未知),统一尺寸并编码,嵌入 FAISS,在 Neo4j 建立 Image 节点;
  - STEP 模型:以 PythonOCC 解析,提取装配层次、零件级几何与拓扑、几何特征(圆柱面/平面)及基于几何关系的装配约束(共轴、共面),输出结构化 JSON,在 Neo4j 建立完整图结构。

  3.4.2 领域本体设计

  ▎ Definition 1(装配工艺本体)。 装配工艺本体定义为四元组 $O=(C,R,H,A)$,其中概念类 $C$
  ▎ 按四个逻辑层级组织:过程结构与上下文层(Doc、Step);物理实体与作业行为层(Action、Material、Equipment、Workstation);数据要素与信息流转层(Param、Sink);多模态资源关联层(Image/ImageExtract、StepModel/StepComponent)。$R$
  ▎ 为关系类型集合,$H$ 为概念层级,$A$ 为约束与公理。

  3.4.3 基于大模型的文本知识抽取

  文本抽取采用 Schema 驱动的结构化抽取:将本体概念序列化为 JSON Schema 注入大模型上下文,利用 LLM
  的函数调用能力将非结构化文本解析转化为"参数填充"任务;结合少样本示例引导;并以精确片段截取策略强制模型从原文截取连续子串,严禁生成式改写,从而在方法层面实现 grounding 约束。输出经自动化解析器做反序列化与完整性校验。

  3.4.4 基于多模态模型的图像知识理解

  图像理解采用"分类—模板引导"两阶段:先由 LMM
  将图像归为六类(语义路由),再对每类施以特有模板按需抽取——流程图抽取步骤序列与流转关系;爆炸图/三维模型图抽取组件列表、装配顺序、几何特征与材料;设备类图像抽取功能、部件与操作要求。

  3.4.5 可溯源三元组与构建流程

  ▎ Definition 2(可溯源三元组)。 一条可溯源三元组定义为 $\hat t=(h,r,t,\sigma)$,其中 $(h,r,t)$ 为本体约束下的标准三元组,$\sigma$ 为来源算子,$\sigma(\hat t)\to d$ 将其映射至来源(文档块、图像或 STEP
  ▎ 组件)。所有实例层知识构成 $\mathcal{K}={\hat t}$。

  知识图谱构建流水线的端到端流程如 Algorithm 1 所示。

  ▎ Algorithm 1 LLM/LMM 驱动的多源异构知识图谱构建

  ▎ 输出: 可溯源知识图谱 K

  ▎ 2:  for each d ∈ D do
  ▎ 3:      预处理: 按类型解析并建立多模态溯源层节点

  ▎ 8:          校验本体一致性与唯一性约束
  ▎ 9:          if 通过 then K ← K ∪ {(h,r,t,σ=d)}
  ▎ 10:         else 登记待人工复核
  ▎ 11: return K

  3.5 装配规划编排智能体(APO):综合知识与视觉信息的序列推导

  APO 是规划阶段的中枢主智能体。它不直接凭直觉给出装配顺序,而是调度 MCP 工具(包括 KG 检索工具)与子智能体(PFA、VES),综合知识图谱中的工艺知识与运行时几何/视觉信息,构建约束图并推导序列。其任务形式化为:
  $$\mathrm{APO}: (\mathcal{G}_{cad},\ \mathcal{K}) \to (S,\ \mathcal{R}) \tag{2}$$

  其中 $\mathcal{G}_{cad}$ 为 STEP 几何,$\mathcal{K}$ 为知识图谱(阶段一离线构建,由 APO 通过 KG 检索工具按需查询),$S$ 为装配序列,$\mathcal{R}$ 为知识缺口。

  3.5.1 信息可信度分级与证据使用规则

  APO 在推导中依据的信息来自异构来源,其可信度与可溯性各不相同。为使智能体对不同来源恰当加权,本文将其组织为五级:

  ▎ Definition 3(信息可信度分级)。 信息空间为偏序集 $\mathcal{E}={L_0,L_1,L_2,L_3,L_4}$,$L_0\prec L_1\prec L_2\prec L_3\prec L_4$:$L_0$ 元数据事实;$L_1$ 几何事实(装配树/包围盒/面/法向/面积/拓扑);$L_2$
  ▎ 视觉制品(以图像路径为凭);$L_3$ 启发式候选(接触候选、清障/拆卸方向、阻挡件,带置信度与方法标记);$L_4$ 智能体推断。$L_0/L_1$ 由 STEP 解析直接给出,$L_2$ 为视觉确认,$L_3$ 明确标注为启发式而非精确求解。

  在此分级之上,APO 遵循一组证据使用规则,以保证结论与其信息来源的可信度相匹配:不得将 $L_3$
  启发式置信度当作事实;不得仅凭零件名称或外观断言功能、材料、过盈、扭矩、焊接、胶接或装配力;不得将直线拆卸方向当作完整机器人路径;不得将工具 JSON 元数据当作视觉证据($L_2$ 必须有图像路径)。形式化地,步骤 $s_i$ 的工艺语义
  $\omega_i$ 被赋高置信,当且仅当其支撑信息 $\mathcal{E}_i$ 含层级不低于阈值 $\tau$ 的来源(即约束 C3)。

  3.5.2 约束图构建

  ▎ Definition 4(约束图)。 装配约束图为有向图 $D=(N,A)$,节点 $N$ 为零件或子装配,边 $A={(n_a,n_b,\delta,\beta,\mathcal{E}{ab})}$ 表示 $n_a$ 优先于 $n_b$,$\delta$
  ▎ 为依赖类型(空间前置、配合顺序、可达性保持、阻挡优先、封闭优先、子装配合并、紧固前置、工装前置),$\beta\in{\mathrm{hard,soft}}$ 区分硬约束与软/推断约束,$\mathcal{E}{ab}$ 为支撑信息引用。$D$ 须无环;环或矛盾依赖登记入
  ▎ $\mathcal{R}$。

  APO 构建 $D$ 时,依据 KG 中的工艺知识与运行时几何/视觉信息共同推导优先边,其优先规则源自工艺本体公理(如内部件先于封盖、定位件先于依赖件、紧固件后于被紧固件、阻挡件后于被阻挡件)。

  3.5.3 证据驱动的多轮规划分析

  APO 区别于单轮大模型推理的核心,是证据驱动的多轮规划分析:候选优先约束来自 KG 工艺知识与运行时接触启发式;APO 综合几何与视觉信息评估每条候选约束的可信度——获得不低于 $\tau$
  层级信息支撑的约束进入高置信结论并写入约束图,信息不足者降级并登记知识缺口,而非强行采纳。其过程如 Algorithm 2。

  ▎ Algorithm 2 APO 证据驱动的多轮规划分析
  ▎ 输入: CAD 几何 G_cad; KG 工艺知识 K; 可信度阈值 τ; 最大轮数 K_max
  ▎ 输出: 装配序列 S; 知识缺口 R
  ▎ 1:  M ← {model_summary, assembly_tree, parts}          // 建立 L0/L1 范围
  ▎ 2:  for each 关键零件 p_i do φ_i ← PFA(p_i)             // 委派特征分析
  ▎ 3:  C ← cad_get_contact_pairs(compact=true)            // L3 接触候选
  ▎ 4:  D ← ∅; R ← ∅
  ▎ 5:  for each 候选约束 c ∈ (K 工艺知识 ∪ C) do            // 候选来自知识与接触启发式
  ▎ 6:      k ← 0; E_c ← 收集信息(c, M)                     // L0/L1
  ▎ 7:      while level(E_c) < τ and k < K_max do
  ▎ 8:          e_vis ← VES(claim=c, G_cad)                 // 补充 L2 视觉信息
  ▎ 9:          E_c ← E_c ∪ {e_vis}; k ← k+1
  ▎ 10:     if level(E_c) ≥ τ then D ← D ∪ {edge(c,β,E_c)}  // 信息充分,采纳
  ▎ 11:     else R ← R ∪ {gap(c,"信息不足",E_c)}             // 信息不足,登记缺口
  ▎ 12: if D has cycle then R ← R ∪ {矛盾依赖}
  ▎ 13: S ← TopologicalSort(D)                              // 满足 C1
  ▎ 14: for each s_i ∈ S do
  ▎ 15:     s_i.ω_i ← ProcessInterface(s_i, K, E)           // 填充 Definition 5
  ▎ 16:     if s_i 无有效 L2 视觉信息 then s_i.conf←low; R←R∪{s_i}
  ▎ 17: return (S, R)

  该过程使每条工艺约束的采纳都与其支撑信息的可信度相匹配(第 10–11 行):信息充分则采纳,不足则显式登记缺口而非强行补全(第 11、16 行),这是本文方法在工业场景下的安全性来源。

  3.6 零件特征分析智能体(PFA):单零件装配特征提取

  PFA 为 APO 的专项子智能体,负责对单个零件做稳定、可追溯的装配特征提取。其任务形式化为:
  $$\mathrm{PFA}: p_i \to \phi_i \tag{3}$$

  PFA 仅调用一次 cad_render_part_multiview(返回 8 视角图像 + compactPart 几何统计),据此分析:

  - 几何类别:plate / disk / shaft / block / ring / fastener_like / spring_like / seal_like / freeform / mixed / unknown;
  - 装配特征:hole / through_hole / blind_hole / shaft / cylindrical_surface / planar_surface / thread_like / slot / notch / boss / step / keyway_like / pin_like / thin_wall / cover_like / orientation_feature;
  - 对称性与方向性:axisymmetric / rotational / mirror / bilateral / asymmetric,并记录缺口、偏心孔、键槽等定向特征;
  - 候选面:区分候选夹持面、装配面、支撑面与需避免接触面;
  - 装夹策略推断:给出候选夹持器/工装类别(如 vacuum_pad / v_block / three_jaw_chuck / magnetic_driver / inner_expansion),但必须标注为工艺推断而非几何事实。

  PFA 严格遵守信息使用规则:compactPart 的平面/圆柱面统计仅作 mesh_heuristic;不得仅凭图片断言材料、磁性、刚度、公差、装配力或螺纹标准,此类信息无外部输入时必须登记为"不确定信息"。

  3.7 视觉证据选择智能体(VES):最小上下文取证

  VES 为 APO 的专项子智能体,职责是以尽量少的上下文,为某一待证明结论捕获并筛选最具信息量的视觉信息。其任务形式化为:
  $$\mathrm{VES}: (\text{claim},\ \mathcal{G}{cad}) \to e{vis} \tag{4}$$

  VES 按目标类型选择工具策略:

  1. 概览:调用 cad_collect_visual_evidence(mode=overview);
  2. 接触对:调用 cad_render_contact_pair_multiview,隔离两零件并以红色高亮候选接触面;
  3. 拆卸/装入方向:调用 cad_render_move_preview,仅在方向假设已提出时使用;
  4. 隐藏界面:调用 cad_collect_visual_evidence(mode=section_sweep) 扫掠剖切。

  VES 的选择准则为:目标零件/接触面可见、运动方向可见、遮挡低、构图完整、视图状态干净、且图像确实支撑结论。若无有用图像,则将信息置空并给出重拍建议,而非强行引用。由于视觉工具共享 viewer 状态,VES
  串行调用,并在每次独立取证前以 cad_reset_view_state 复位。

  3.8 带工艺语义且可溯源的装配序列输出

  经 Algorithm 2 得到的序列遵循统一结构化模式,每步携带工艺接口规范。

  ▎ Definition 5(工艺接口规范)。 步骤 $s_i$ 的工艺语义 $\omega_i=(\mathrm{prim},(B,M),F,\Theta,\Gamma)$:$\mathrm{prim}$ 为工艺原语(平面配合、圆柱插入、轴孔插入、螺纹紧固、堆叠、封盖等);$(B,M)$
  ▎ 为基座件/移动件角色划分;$F$ 为配合/支撑/对齐面引用;$\Theta$ 为姿态要求(接近方向、插入轴、旋转轴、姿态约束);$\Gamma$ 为工装要求(候选夹持器、夹持面、需保持清空面、所需能力及尚缺外部输入)。

  这些字段被定位为指导下游柔性装配台/机器人规划的候选工艺意图,而非最终轨迹或确定夹具设计。结合每步绑定的信息引用 $\mathcal{E}_i$ 与来源算子 $\sigma$,整条序列实现从设计文档到装配步骤的逐步可溯源。

  ▎ 关于视觉理解的说明。 装配产品的视觉理解仍是开放难题。本文不声称解决该难题,而是通过 VES、多视角/剖切渲染工具与主从编排,在前述证据使用规则下最大化可获取的视觉信息,并对视觉不确定步显式标记待人工复核(Algorithm 2 第 16
  ▎ 行),而非强行判断。
