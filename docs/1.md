## 3 方法(Method)

### 3.1 总体架构

本文提出一种面向成套工艺语义的知识图谱与多智能体相结合的装配序列生成方法(见图 1)。其核心思想包含两个相互衔接的部分:

其一,以知识图谱作为多源异构数据的高效组织与外部获取方式。产品的设计文档、工艺图像与 STEP 模型分散、异构且语义不互通,直接交由大模型逐次检索既低效又难以复用。本文将这些散落知识在领域本体约束下抽取、互联并沉淀为一个结构化、可溯源的知识图谱,使工艺语义以统一、可查询的组织形式持久存在,为下游规划提供稳定的外部知识来源。

其二,以多智能体依据知识图谱知识与视觉信息协同完成装配序列的规划分析。在序列推导阶段,多智能体一方面经知识检索获取与零件、配合关系相关的工艺语义知识,另一方面调用 STEP 运行时几何与多视角视觉信息,综合二者对装配优先关系、配合方式与工艺语义进行规划分析;当所获知识与视觉信息不足以支撑某一判断时,系统显式登记知识缺口,而非强行给出结论。

由此,知识图谱负责“知识从哪来、如何高效组织”,多智能体负责“如何依据知识与视觉信息推理出装配序列”。该方法以产品的 CAD/STEP 模型与多源异构设计/工艺知识为输入,以一条带成套工艺语义且每步可溯源的装配序列为输出。整体流程细分为两个阶段:

- **阶段一(知识构建)**:一条 LLM/LMM 驱动的离线知识图谱构建流水线,从多源异构文件(工艺文档、图像、STEP 模型)中,在领域本体约束下抽取实体、关系与属性,将散落知识一次性编译为持久化、可溯源、可增量维护的工艺知识图谱,供阶段二的规划智能体按需检索。
- **阶段二(序列规划)**:采用主从编排式(orchestrator–specialist)多智能体范式,由一个编排主智能体与三个专项子智能体协同完成——**装配规划编排智能体(Assembly Planning Orchestrator, APO)** 为主智能体;**知识检索智能体(Knowledge Retrieval Agent, KRA)**、**零件特征分析智能体(Part-Feature Analysis Agent, PFA)** 与**视觉证据选择智能体(Visual-Evidence Selection Agent, VES)** 为专项子智能体。APO 理解任务、评估复杂度并按需调度子智能体,综合各方返回的工艺知识、零件特征与视觉信息推导装配序列;KRA、PFA、VES 分别承担知识检索、零件级特征提取与视觉取证。

**总体流程。** 阶段一离线完成知识编译,产出持久化知识图谱 $\mathcal{K}$(§3.4);阶段二由 APO 以主从编排方式动态驱动。该流程并非固定流水线,而是 APO 依据任务状态按需调度子智能体的迭代过程,可归纳为四个环节(对应 Algorithm 2):

1. **任务理解与范围建立。** APO 接收 CAD/STEP 模型与规划目标,调用模型范围工具获取装配树、零件清单与包围盒等几何事实,评估装配体规模与复杂度,据此规划后续需要哪些子智能体介入、对哪些关键零件与配合关系优先取证;
2. **按需委派专项子智能体。** APO 根据子任务类型,动态分配持有对应提示词、工具与技能包(Skill)的专项子智能体,各自装载专长并返回结构化结果:需要工艺语义知识时委派 **KRA** 检索知识图谱、返回可溯源三元组;需要零件级特征时委派 **PFA** 提取几何类别、装配特征与候选夹持面;需要空间确认时委派 **VES** 捕获接触面、运动方向等视觉信息;
3. **综合分析与约束推导。** APO 汇聚 KRA 的工艺知识、PFA 的零件特征与运行时接触启发式,形成候选优先约束集;对每条候选约束,综合几何与视觉信息评估其可信度,必要时再次委派 VES 补充视觉信息并迭代;信息充分者采纳并写入约束图 $D$,不足者降级并登记知识缺口 $\mathcal{R}$;
4. **序列生成与输出。** APO 对约束图 $D$ 作拓扑排序得到装配序列 $S$,为每步填充工艺接口规范并绑定其支撑信息来源,最终输出带工艺语义且逐步可溯源的装配序列 $S$ 与知识缺口报告 $\mathcal{R}$。

该流程的关键在于:APO 是决策中枢而非顺序执行器——它判断“当前需要什么、该问谁”,再将专业子任务下放给装载了对应 Skill 的子智能体,自身专注于知识与信息的综合及序列推导。子智能体之间互不通信,均经 APO 中转,保证控制流确定、可复现。两阶段以“构建—消费”职责解耦为基本原则:多智能体编排仅作用于知识的规划性消费,而非构建侧的三元组抽取。各智能体的角色、专属工具、可加载技能包与输入/输出接口如表 2 所示。

### 3.2 规划智能体构建范式

本文四个规划智能体(APO、KRA、PFA、VES)共享统一的构建范式。本节阐明范式的设计选择、有效性来源及其核心机制。

#### 3.2.1 主从编排式多智能体框架与智能体构成

各智能体基于 MCP(Model Context Protocol)框架构建(见图 2)。其运行流程如下:当规划需求被发起时(Step 1),控制器代码经 MCP 接口调用智能体模块;智能体内部与 LLM/LMM 交互(Step 2),根据任务动态选择工具并分解执行(Step 3)。基于 MCP 框架定义的智能体可通过结构化输出约束与多轮对话实现自反思与迭代改进,持续优化其响应质量。

每个规划智能体由四个要素组合构成其专家能力:(i) **三阶段提示词**(§3.2.2)界定角色、依据与输出要求;(ii) **专属 MCP 工具**提供与运行时环境交互的外部能力(几何解析、视觉渲染、KG 查询等);(iii) **可加载技能包(Skill)**——针对特定子任务封装领域启发式与操作规程的模块,在智能体被调度时按需加载,使其即时装载对应专长而非依赖通用推理临场发挥;(iv) **结构化输出契约**以 JSON Schema 规定返回字段,确保结果可被 APO 直接解析、聚合与追溯。

本文采用主从编排式(orchestrator–specialist)范式而非单体大模型端到端输出。这一选择源于装配序列规划任务的内在结构:它天然可分解为“全局序列编排”与若干“专项取证”子任务,且各子任务所需的能力、上下文与信息类型互不相同。据此设置一个中枢编排者(APO)与三个专项执行者(KRA、PFA、VES),使控制流确定、职责边界清晰。该范式的有效性来自三条独立机制:

1. **职责分解抑制知识漂移。** 将全任务分解到边界清晰的专项智能体后,每个智能体仅在受限上下文与明确能力边界内工作,从源头压缩幻觉发生空间;
2. **主从编排匹配任务中枢依赖结构。** 装配序列推导存在天然中枢——约束图构建与拓扑排序须由统揽全局者完成,而知识、特征与视觉信息是按需调用的局部服务。主从关系使控制流确定、可复现,避免对等协商带来的不可控收敛与冗余通信;
3. **工具与技能装载将“猜测”约束为“有据可依的推断”。** APO 自身无需具备全部专长,而是在判断子任务类型后,调度持有对应提示词、工具与 Skill 的专项子智能体完成专业子任务;各智能体的结论须绑定外部信息来源,使模型输出从“基于参数记忆的生成”转变为“基于外部信息的推断”。

#### 3.2.2 三阶段提示词设计

通过引入 LLM/LMM 作为智能体的推理核心,每个智能体的能力通过三阶段提示词设计增强。三阶段提示词设计通过结构化框架实现任务驱动执行与逻辑引导:

1. **角色定位阶段**:按任务需求分配专业身份(如 APO 为“装配规划编排专家”、KRA 为“工艺知识检索专家”、PFA 为“单零件装配特征分析专家”、VES 为“视觉证据选择专家”),明确知识体系与能力边界,将模型严格约束在指定专业域内生成,从源头减少因角色模糊导致的知识漂移与幻觉;
2. **任务依据与输入信息阶段**:系统化注入多源数据与工具资源——明确输入数据覆盖的关键要素并清晰定义所需工具及其功能,为模型提供稳健的上下文支撑,防止因信息缺失而产生幻觉,有效约束生成内容不偏离事实依据;
3. **具体任务要求阶段**:以渐进逻辑构建任务体系并明确输出格式;通过任务概述与示例描述确保输出格式一致性与逻辑严密性,防止模型在复杂推理中出现逻辑断裂与内容发散。

三阶段提示词构成闭环任务执行引导:角色定位约束“以谁的身份做”,任务依据约束“基于什么做”,任务要求约束“做成什么样且不得越界”,对应范式中“职责分解”机制在单个智能体内部的落地。

#### 3.2.3 专家评审与人在回路验证

为进一步验证各智能体核心输出的有效性与可靠性,本文为每个智能体的关键输出建立专家评审机制(见表 3)。该机制将“人在回路”显式建模为系统的一个质量环节:对低置信或信息不足的输出,转入人工复核而非直接采纳。

**表 3 各智能体输出的专家评审维度**

| 智能体 | 评审维度 |
|--------|----------|
| APO | 每步是否引用数据+视觉信息;置信度是否与信息可信度匹配;知识缺口是否如实报告 |
| KRA | 返回三元组是否实际存在于图谱;来源算子 σ 是否可回链;无匹配时是否如实返回空集 |
| PFA | 几何类别判断是否有视觉/统计支撑;装夹推断是否标注为推断而非事实;不确定信息是否如实登记 |
| VES | 所选图像是否真实存在;目标零件/接触面是否可见;图像是否支撑待证明结论 |

### 3.3 问题形式化

给定由 $n$ 个零件构成的产品,记零件集合为 $P={p_1,\dots,p_n}$。方法输入为三元组 $(\mathcal{G}_{cad},\mathcal{V},\mathcal{K})$:$\mathcal{G}_{cad}$ 为 STEP 解析的几何信息,$\mathcal{V}$ 为按需获取的视觉信息,$\mathcal{K}$ 为知识图谱工艺语义知识。

目标为求一条装配序列 $S=\langle s_1,\dots,s_n\rangle$,每步 $s_i=(p_{\pi(i)},\omega_i,\mathcal{E}_i)$ 携带零件、工艺语义 $\omega_i$(Definition 5)与信息引用 $\mathcal{E}_i$,$\pi$ 为 $P$ 的排列。所求序列须满足:

- (C1) $S$ 是约束图 $D$(Definition 4)的拓扑排序;
- (C2) 每步沿声明方向无碰撞;
- (C3) 每步 $\omega_i$ 由不低于阈值层级 $\tau$ 的信息支撑(Definition 3)。

当知识不足以满足 (C3) 时,登记知识缺口 $\mathcal{R}$。方法输出为二元组 $(S,\mathcal{R})$。装配序列生成由此被刻画为:知识图谱工艺知识与运行时证据共同支撑的带工艺语义拓扑排序搜索问题。

### 3.4 多源异构装配工艺知识图谱构建

阶段一的知识图谱构建为一条 LLM/LMM 驱动的离线流水线,负责将散落于多源异构文件中的离散知识,一次性编译为语义清晰、可溯源的知识图谱,供阶段二规划智能体通过 KRA 按需查询。其任务形式化为:
$$
\mathrm{KG\text{-}Pipeline}: (\mathcal{D},\ O) \to \mathcal{K},\qquad \mathcal{D}={d_{pdf}, d_{img}, d_{step}} \tag{1}
$$

其中 $\mathcal{D}$ 为多源异构文件集合,$O$ 为领域本体,$\mathcal{K}$ 为可溯源知识图谱。产出 $\mathcal{K}$ 在逻辑上分为三层:**多模态溯源层**(保存文档块、图像与 STEP 组件的原始制品,作为不可变事实来源)、**实例层**(由大模型抽取、去重后写入的可溯源三元组集合)、**模式层**(领域本体 $O$,规定概念类型、关系语义与一致性公理)。

> **构建侧范式选择。** 与将多智能体编排投入 KG 构建侧的近期工作(MA-APKG [Pu et al., 2026]、KARMA [Lu & Wang, 2025])不同,本文主张在装配工艺场景下,KG 构建可由一条 LLM/LMM 驱动的离线流水线经济地完成,而多智能体的价值应转移到知识的规划性消费侧(§3.5)。

#### 3.4.1 知识获取与预处理

原始文件先经结构化管理与向量化预处理,以建立多模态溯源层。按文件类型分别处理:

- **工艺文档(PDF)**:以 PyMuPDF 解析获取文本、图片与图文关联;采用递归字符分块在可控长度下保留语义关联;文本块经嵌入存入 FAISS 向量库,并在 Neo4j 中建立 Document—Chunk—Image 节点结构;
- **图像**:按工艺语义归为六类(装配工艺流程图、零件三维模型图、产品爆炸图、设备实物图、设备示意图、未知),统一尺寸并编码,嵌入 FAISS,在 Neo4j 建立 Image 节点;
- **STEP 模型**:以 PythonOCC 解析,提取装配层次、零件级几何与拓扑、几何特征(圆柱面/平面)及基于几何关系的装配约束(共轴、共面),输出结构化 JSON,在 Neo4j 建立完整图结构。

#### 3.4.2 领域本体设计

> **Definition 1(装配工艺本体)。** 装配工艺本体定义为四元组 $O=(C,R,H,A)$,其中概念类 $C$ 按四个逻辑层级组织:过程结构与上下文层(Doc、Step);物理实体与作业行为层(Action、Material、Equipment、Workstation);数据要素与信息流转层(Param、Sink);多模态资源关联层(Image/ImageExtract、StepModel/StepComponent)。$R$ 为关系类型集合(如 HAS_CHUNK、HAS_IMAGE、HAS_COMPONENT、HAS_ASSEMBLY_RELATION 等),$H$ 为概念层级,$A$ 为约束与公理(唯一性约束实现同名实体自动归并去重,多维索引保障跨模态检索效率)。

#### 3.4.3 基于大模型的文本知识抽取

文本抽取采用 Schema 驱动的结构化抽取:将本体概念序列化为 JSON Schema 注入大模型上下文,利用 LLM 的函数调用能力将非结构化文本解析转化为“参数填充”任务;结合少样本示例引导;并以精确片段截取策略强制模型从原文截取连续子串,严禁生成式改写,从而在方法层面实现 grounding 约束。输出经自动化解析器做反序列化与完整性校验,确保每条知识在格式与类型上符合本体定义。

#### 3.4.4 基于多模态模型的图像知识理解

图像理解采用“分类—模板引导”两阶段:先由 LMM 将图像归为六类(语义路由),再对每类施以特有模板按需抽取——流程图抽取步骤序列与流转关系;爆炸图/三维模型图抽取组件列表、装配顺序、几何特征与材料;设备类图像抽取主要功能、关键部件与操作注意事项。

#### 3.4.5 可溯源三元组与构建流程

> **Definition 2(可溯源三元组)。** 一条可溯源三元组定义为 $\hat t=(h,r,t,\sigma)$,其中 $(h,r,t)$ 为本体约束下的标准三元组,$\sigma$ 为来源算子,$\sigma(\hat t)\to d$ 将其映射至来源(文档块、图像或 STEP 组件)。所有实例层知识构成 $\mathcal{K}={\hat t}$,并以 Neo4j 图存储、FAISS 向量索引支持跨模态检索。

知识图谱构建流水线的端到端流程如 Algorithm 1 所示。

> **Algorithm 1 LLM/LMM 驱动的多源异构知识图谱构建**
> 
> **输入:** 多源文件 $D=\{d_{pdf}, d_{img}, d_{step}\}$; 领域本体 $O=(C,R,H,A)$  
> **输出:** 可溯源知识图谱 $\mathcal{K}$
> 
> 1:  $\mathcal{K} \leftarrow \emptyset$  
> 2:  **for each** $d \in D$ **do**  
> 3:       预处理: 按类型解析并建立多模态溯源层节点(嵌入 FAISS)  
> 4:       **if** $d$ 为文本 **then**  $T_d \leftarrow \mathrm{LLM}(\text{chunks} \mid \text{Schema}(O), \text{少样本}, \text{精确截取})$  
> 5:       **elif** $d$ 为图像 **then** $T_d \leftarrow \mathrm{LMM}(d \mid \text{分类模板})$  
> 6:       **else**              $T_d \leftarrow \text{几何关系转三元组(PythonOCC解析结果)}$  
> 7:       **for each** $(h,r,t) \in T_d$ **do**  
> 8:             校验本体一致性与唯一性约束(类型合法; 去重归并)  
> 9:             **if** 通过 **then**  $\mathcal{K} \leftarrow \mathcal{K} \cup \{(h,r,t,\sigma=d)\}$  \# 绑定来源, 写入 Neo4j  
> 10:            **else**  登记待人工复核(专家评审机制)  
> 11: **return** $\mathcal{K}$

### 3.5 装配规划编排智能体(APO):综合知识与视觉信息的序列推导

APO 是规划阶段的中枢主智能体。它不直接凭直觉给出装配顺序,而是调度 MCP 工具与子智能体(KRA、PFA、VES),综合知识图谱中的工艺知识与运行时几何/视觉信息,构建约束图并推导序列。其任务形式化为:
$$
\mathrm{APO}: (\mathcal{G}_{cad},\ \mathcal{K}) \to (S,\ \mathcal{R}) \tag{2}
$$

其中 $\mathcal{G}_{cad}$ 为 STEP 几何,$\mathcal{K}$ 为知识图谱(阶段一离线构建,由 APO 经 KRA 按需查询),$S$ 为装配序列,$\mathcal{R}$ 为知识缺口。

#### 3.5.1 信息可信度分级与证据使用规则

APO 在推导中依据的信息来自异构来源,其可信度与可溯性各不相同。为使智能体对不同来源恰当加权,本文将其组织为五级:

> **Definition 3(信息可信度分级)。** 信息空间为偏序集 $\mathcal{E}=\{L_0,L_1,L_2,L_3,L_4\}$,$L_0\prec L_1\prec L_2\prec L_3\prec L_4$:
> - $L_0$: 元数据事实;
> - $L_1$: 几何事实(装配树/包围盒/面/法向/面积/拓扑);
> - $L_2$: 视觉制品(以图像路径为凭);
> - $L_3$: 启发式候选(接触候选、清障/拆卸方向、阻挡件,带置信度与方法标记);
> - $L_4$: 智能体推断。
> 
> $L_0/L_1$ 由 STEP 解析直接给出,$L_2$ 为视觉确认,$L_3$ 明确标注为启发式而非精确求解。

在此分级之上,APO 遵循一组证据使用规则,以保证结论与其信息来源的可信度相匹配:不得将 $L_3$ 启发式置信度当作事实;不得仅凭零件名称或外观断言功能、材料、过盈、扭矩、焊接、胶接或装配力;不得将直线拆卸方向当作完整机器人路径;不得将工具 JSON 元数据当作视觉证据($L_2$ 必须有图像路径)。形式化地,步骤 $s_i$ 的工艺语义 $\omega_i$ 被赋高置信,当且仅当其支撑信息 $\mathcal{E}_i$ 含层级不低于阈值 $\tau$ 的来源(即约束 C3)。

#### 3.5.2 约束图构建

> **Definition 4(约束图)。** 装配约束图为有向图 $D=(N,A)$,节点 $N$ 为零件或子装配,边 $A=\{(n_a,n_b,\delta,\beta,\mathcal{E}_{ab})\}$ 表示 $n_a$ 优先于 $n_b$,$\delta$ 为依赖类型(空间前置、配合顺序、可达性保持、阻挡优先、封闭优先、子装配合并、紧固前置、工装前置),$\beta\in\{\mathrm{hard,soft}\}$ 区分硬约束与软/推断约束,$\mathcal{E}_{ab}$ 为支撑信息引用。$D$ 须无环;环或矛盾依赖登记入 $\mathcal{R}$。

APO 构建 $D$ 时,依据 KRA 返回的工艺知识与运行时几何/视觉信息共同推导优先边,其优先规则源自工艺本体公理(如内部件先于封盖、定位件先于依赖件、紧固件后于被紧固件、阻挡件后于被阻挡件)。

#### 3.5.3 证据驱动的多轮规划分析

APO 区别于单轮大模型推理的核心,是**证据驱动的多轮规划分析**:候选优先约束来自 KRA 检索的工艺知识与运行时接触启发式;APO 综合几何与视觉信息评估每条候选约束的可信度——获得不低于 $\tau$ 层级信息支撑的约束进入高置信结论并写入约束图,信息不足者降级并登记知识缺口,而非强行采纳。其过程如 Algorithm 2。

> **Algorithm 2 APO 证据驱动的多轮规划分析**
> 
> **输入:** CAD 几何 $\mathcal{G}_{cad}$; 知识图谱 $\mathcal{K}$; 可信度阈值 $\tau$; 最大轮数 $K_{max}$  
> **输出:** 装配序列 $S$; 知识缺口 $\mathcal{R}$
> 
> 1:  $M \leftarrow \{\text{model\_summary, assembly\_tree, parts}\}$          \# 任务理解: 建立 L0/L1 范围  
> 2:  **for each** 关键零件 $p_i$ **do** $\phi_i \leftarrow \mathrm{PFA}(p_i)$             \# 委派特征分析  
> 3:  $\hat{T} \leftarrow \mathrm{KRA}(\text{知识需求}, \mathcal{K})$                                \# 委派检索: 返回可溯源工艺知识  
> 4:  $C \leftarrow \mathrm{cad\_get\_contact\_pairs(compact=true)}$            \# L3 接触候选  
> 5:  $D \leftarrow \emptyset$; $\mathcal{R} \leftarrow \emptyset$  
> 6:  **for each** 候选约束 $c \in (\hat{T} \cup C)$ **do**                    \# 候选来自知识与接触启发式  
> 7:       $k \leftarrow 0$; $E_c \leftarrow \text{收集信息}(c, M)$                     \# L0/L1  
> 8:       **while** $\mathrm{level}(E_c) < \tau$ **and** $k < K_{max}$ **do**  
> 9:             $e_{vis} \leftarrow \mathrm{VES}(\text{claim}=c, \mathcal{G}_{cad})$                 \# 补充 L2 视觉信息  
> 10:            $E_c \leftarrow E_c \cup \{e_{vis}\}$; $k \leftarrow k+1$  
> 11:      **if** $\mathrm{level}(E_c) \ge \tau$ **then** $D \leftarrow D \cup \{\mathrm{edge}(c,\beta,E_c)\}$  \# 信息充分, 采纳  
> 12:      **else** $\mathcal{R} \leftarrow \mathcal{R} \cup \{\mathrm{gap}(c,\text{"信息不足"},E_c)\}$             \# 信息不足, 登记缺口  
> 13: **if** $D$ has cycle **then** $\mathcal{R} \leftarrow \mathcal{R} \cup \{\text{矛盾依赖}\}$  
> 14: $S \leftarrow \mathrm{TopologicalSort}(D)$                              \# 满足 C1  
> 15: **for each** $s_i \in S$ **do**  
> 16:       $s_i.\omega_i \leftarrow \mathrm{ProcessInterface}(s_i, \hat{T}, E)$           \# 填充 Definition 5  
> 17:       **if** $s_i$ 无有效 L2 视觉信息 **then** $s_i.\mathrm{conf} \leftarrow \mathrm{low}$; $\mathcal{R} \leftarrow \mathcal{R} \cup \{s_i\}$  
> 18: **return** $(S, \mathcal{R})$

该过程使每条工艺约束的采纳都与其支撑信息的可信度相匹配(第 11–12 行):信息充分则采纳,不足则显式登记缺口而非强行补全(第 12、17 行),这是本文方法在工业场景下的安全性来源。

### 3.6 知识检索智能体(KRA):本体约束下的可溯源知识检索

KRA 为 APO 的专项子智能体,负责将 APO 的知识需求转化为对知识图谱的结构化查询,并返回可溯源的工艺语义知识。其任务形式化为:
$$
\mathrm{KRA}: (\text{need},\ \mathcal{K}) \to \hat{T},\qquad \hat{T}=\{\hat t_1,\dots,\hat t_m\} \tag{3}
$$

其中 $\text{need}$ 为 APO 下达的知识需求(如“零件 $p_a$ 与 $p_b$ 的配合类型与连接工艺”),$\hat{T}$ 为返回的可溯源三元组集合,每条 $\hat t=(h,r,t,\sigma)$ 携带来源算子 $\sigma$(Definition 2)。

不同于将大子图一次性注入上下文的检索增强方式(社区摘要会损失精确约束,冗余子图不可溯),KRA 采用**模式引导、索引优先、本体约束下的类型化多跳检索**,逐跳按需取证,经三个 MCP 工具实现:

1. **模式层引导(查询规划)**:KRA 首先以 `kg_schema_peek` 读取领域本体 $O$ 作为导航地图,将 $\text{need}$ 映射为本体上的查询计划——确定相关的实体类型与关系类型,从而把开放式知识需求收敛为类型受限的检索目标;
2. **入口实体定位(锚定)**:以 `kg_entity_resolve` 在实例层定位种子实体——借助 FAISS 语义检索处理同义/别名表述,并以本体的唯一性约束完成“模糊名→标准实体”消歧,得到锚点;
3. **类型化多跳遍历(下钻)**:以 `kg_path_query` 自锚点出发,仅沿本体允许的关系类型作多跳路径检索(Neo4j Cypher),按需扩展邻域并逐跳返回三元组;每跳经 $\sigma$ 绑定其文档块/图像/STEP 组件来源,使返回知识整体可回链原文。

KRA 严格遵守证据使用规则:仅返回知识图谱中实际存在的三元组及其来源,不得生成式补全图谱中不存在的关系;当查询计划在图谱中无匹配路径时,返回空集并标注为知识缺口,交由 APO 处理(Algorithm 2 第 12 行),而非臆测。

### 3.7 零件特征分析智能体(PFA):单零件装配特征提取

PFA 为 APO 的专项子智能体,负责对单个零件做稳定、可追溯的装配特征提取。其任务形式化为:
$$
\mathrm{PFA}: p_i \to \phi_i \tag{4}
$$

PFA 仅调用一次 `cad_render_part_multiview`(返回 8 视角图像 + compactPart 几何统计),据此分析:

- **几何类别**:`plate` / `disk` / `shaft` / `block` / `ring` / `fastener_like` / `spring_like` / `seal_like` / `freeform` / `mixed` / `unknown`;
- **装配特征**:`hole` / `through_hole` / `blind_hole` / `shaft` / `cylindrical_surface` / `planar_surface` / `thread_like` / `slot` / `notch` / `boss` / `step` / `keyway_like` / `pin_like` / `thin_wall` / `cover_like` / `orientation_feature`;
- **对称性与方向性**:`axisymmetric` / `rotational` / `mirror` / `bilateral` / `asymmetric`,并记录缺口、偏心孔、键槽等定向特征;
- **候选面**:区分候选夹持面、装配面、支撑面与需避免接触面;
- **装夹策略推断**:给出候选夹持器/工装类别(如 `vacuum_pad` / `v_block` / `three_jaw_chuck` / `magnetic_driver` / `inner_expansion`),但必须标注为工艺推断而非几何事实。

PFA 严格遵守信息使用规则:`compactPart` 的平面/圆柱面统计仅作 mesh_heuristic;不得仅凭图片断言材料、磁性、刚度、公差、装配力或螺纹标准,此类信息无外部输入时必须登记为“不确定信息”。

### 3.8 视觉证据选择智能体(VES):最小上下文取证

VES 为 APO 的专项子智能体,职责是以尽量少的上下文,为某一待证明结论捕获并筛选最具信息量的视觉信息。其任务形式化为:
$$
\mathrm{VES}: (\text{claim},\ \mathcal{G}_{cad}) \to e_{vis} \tag{5}
$$

VES 按目标类型选择工具策略:

1. **概览**:调用 `cad_collect_visual_evidence(mode=overview)`;
2. **接触对**:调用 `cad_render_contact_pair_multiview`,隔离两零件并以红色高亮候选接触面;
3. **拆卸/装入方向**:调用 `cad_render_move_preview`,仅在方向假设已提出时使用;
4. **隐藏界面**:调用 `cad_collect_visual_evidence(mode=section_sweep)` 扫掠剖切。

VES 的选择准则为:目标零件/接触面可见、运动方向可见、遮挡低、构图完整、视图状态干净、且图像确实支撑结论。若无有用图像,则将信息置空并给出重拍建议,而非强行引用。由于视觉工具共享 viewer 状态,VES 串行调用,并在每次独立取证前以 `cad_reset_view_state` 复位。

### 3.9 带工艺语义且可溯源的装配序列输出

经 Algorithm 2 得到的序列遵循统一结构化模式,每步携带工艺接口规范。

> **Definition 5(工艺接口规范)。** 步骤 $s_i$ 的工艺语义 $\omega_i=(\mathrm{prim},(B,M),F,\Theta,\Gamma)$:
> - $\mathrm{prim}$: 工艺原语(平面配合、圆柱插入、轴孔插入、螺纹紧固、堆叠、封盖等);
> - $(B,M)$: 基座件/移动件角色划分;
> - $F$: 配合/支撑/对齐面引用;
> - $\Theta$: 姿态要求(接近方向、插入轴、旋转轴、姿态约束);
> - $\Gamma$: 工装要求(候选夹持器、夹持面、需保持清空面、所需能力及尚缺外部输入)。

这些字段被定位为指导下游柔性装配台/机器人规划的候选工艺意图,而非最终轨迹或确定夹具设计。结合每步绑定的信息引用 $\mathcal{E}_i$ 与来源算子 $\sigma$,整条序列实现从设计文档到装配步骤的逐步可溯源。

>
